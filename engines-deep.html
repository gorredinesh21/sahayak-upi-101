02 · The direct answer

What exactly IS Cognee?

Short version: a Python library you pip install — real, readable source code on GitHub, Apache-2.0 licensed. Not markdown files, not a database, not a model, not a website. Its job: take your data, use an LLM to extract entities and relationships, store them as a knowledge graph + vectors on your disk, and answer natural-language queries over them. "Memory as a library."

✅ What it IS

  • Source code — a git repo (github.com/topoteretes/cognee) you can read line-by-line, fork, or modify; Apache-2.0 = free for any use, forever
  • A pipeline builder: text in → chunk → LLM extracts facts ("Case #101 stalled at SBI") → graph + vector stores written to local files by default
  • A query engine: natural-language questions in, answers synthesized from the graph out
  • Provider-agnostic — it calls whatever LLM you configure (we point it at Sarvam, or run it fully local with Ollama = ₹0)
  • In-process: import cognee inside our backend. No separate service, no daemon, no UI to babysit

❌ What it is NOT

  • Not markdown files or docs — nothing to "read into" the model; it's engineering code
  • Not a model — it contains no intelligence; it borrows ours (Sarvam) for extraction
  • Not a database — it uses stores (NetworkX graph + LanceDB vectors by default; can swap Neo4j/Postgres later)
  • Not a chatbot or agent framework — it never talks to users; only our loop calls it
  • Not cloud-locked — no account, no API key of theirs needed for the self-hosted library
💡 The mental model: Cognee is to case history what a librarian is to books. The books are our closed case files. When a new case arrives, the agent asks the librarian ("how did similar cases go?") and gets an answer in plain language — instead of us hand-writing SQL against a pile of logs. The librarian's reading skills come from Sarvam; the filing cabinets are local files; the librarian's method is Cognee's open-source code.

async def on_case_closed(case):
    summary = render_case_file(case)   # our formatter → plain text case file
    await cognee.remember(summary)      # chunks → extracts → graph grows
    # e.g. text: "Case #101. Z5 debit-credit fail at SBI, ₹2,800,
    #   ben=shop@ybl, auto-reversal landed in 26h, customer satisfied."
    # Cognee+Sarvam extract: (Case#101)-[code]->(Z5), (Case#101)-[bank]->(SBI),
    #   (Case#101)-[resolved_in]->(26h), (shop@ybl)-[ben_of]->(Case#101) ...
Python · READ — called inside the agent loop before deciding
async def memory_context(brief):
    q = f"similar {brief['resp_code']} cases at {brief['ben_bank']}: "
       "count, median resolution hours, and whether {brief['ben_vpa']} "
       "appeared in any prior case"
    results = await cognee.recall(query_text=q)
    return "\n".join(r.text for r in results)
    # → "3 prior Z5 cases at SBI, median 26h. shop@ybl seen in Case#099 (fraud report)."
    # this string is injected into the Case Brief the LLM sees ↓
🧮 Cost honesty: remember() also spends LLM tokens (extraction) — with Gemini's free tier that's ₹0 for our volumes; with Ollama it's ₹0 forever. recall() is cheaper still. The only real spend in the whole system is Sarvam voice.

🆚 Why not just SQL?

SQL needs you to predict every question. A graph answers relationship questions you never designed for: "which VPAs link to fraud-reported cases through shared beneficiaries?", "which bank's stalls repeat?". Same files, but the edges are first-class. (And on stage: "the agent remembers every case it has ever closed" is a sponsor-story sentence SQL can't buy.)

05 · The AI part we write

The agent loop — ~80 lines that are the product

The LLM never runs wild. It sits inside our loop, which owns the tools, the budget of steps, and the hard rails. This skeleton is the heart of the demo — and every line of it is ours.

Python · the brain client — Gemini via Vertex on our GCP (no OpenAI, no API key)
from google import genai

llm = genai.Client(vertexai=True,               # ✨ Vertex AI — our GCP subscription
                   project="personal-project-dg21",
                   location="us-central1")     # auth = gcloud ADC. No key. No OpenAI import.

def llm_chat(prompt_msgs):
    return llm.models.generate_content(
        model="gemini-3-flash",               # pin exact id from docs at build
        contents=prompt_msgs,
        config=genai.types.GenerateContentConfig(
            tools=TOOL_SPECS))                   # function-calling = tool choice
Python · backend/agent.py — annotated skeleton
SYSTEM = """You are Sahayak, Paytm's failed-payments agent.
You get a CASE_BRIEF (JSON). Decide ONE action per turn:
(a) a tool call, (b) a customer message, or (c) ESCALATE.
Rules: never claim to reverse money yourself; if fraud_score > 0.7
or amount > ₹10,000 with first_time_beneficiary → escalate, never act.
Always quote RRN and real ETA from MEMORY. Reply in customer's language."""

TOOLS = {"check_bank_status": check_bank_status,   # ← our mock-rail functions
        "check_npci":      check_npci,
        "file_complaint":  file_complaint,
        "set_sla_timer":   set_sla_timer,
        "send_update":     send_update,
        "escalate":        escalate}

async def run_case(case):                          # ①  our code: brief assembly
    brief = build_case_brief(case)                   #    15 fields, pre-computed
    brief["memory"] = await memory_context(brief) # ②  Cognee recall()→string
    msgs = [{"role":"system","content": SYSTEM},
            {"role":"user","content": json.dumps(brief)}]

    for turn in range(MAX_TURNS):                     # ③  RAIL: hard step budget
        r = llm_chat(msgs)                           # ④  ✨ Gemini: the decision
        if r.tool_call:                              # ⑤  LLM chose a tool
            fn   = TOOLS[r.tool_call.name]           #    we look it up — only these exist
            out  = await fn(**r.tool_call.args) # ⑥  OUR code executes it
            msgs.append(tool_result(out))            # ⑦  result fed back to LLM
            ui.emit("thinking", r.tool_call, out)  # ⑧  thinking-view beat
        else:                                          # ⑨  LLM chose to speak
            await send_update(r.text)              #    text → customer channel
            wav = sarvam_tts(r.text_hi, "bulbul:v3") # ⑩  🗣️ Sarvam voice note
            await send_voice(wav)
            break

    if case.state == "closed":
        await cognee.remember(render_case_file(case)) # ⑪ memory grows

🧩 What's ours

The prompt & rules, the tool functions, the loop budget, the brief builder, the guardrails (idempotent complaints, thresholds, the never-list), the UI timeline. The judgment skeleton.

✨ What's Gemini's

Each llm_chat() is one HTTPS call — the decision itself: which tool, or speak, or escalate. Function-calling reliability is why it's the brain; the free tier (~1,500 req/day) is why it's free.

🗣️ What's Sarvam's

Voice only: sarvam_tts() turns the agent's Hindi line into a WhatsApp voice note; STT turns the customer's voice reply back into text for Gemini.

🧠 What's Cognee's

Two calls in this file: memory_context() (recall) before deciding, remember() after closing. The graph lives on our disk between them; Gemini does its extraction.

🔒 The rails, stated in code: the LLM can only call functions that exist in TOOLS; it gets at most MAX_TURNS steps; file_complaint refuses a second filing for the same RRN (idempotent); and the escalation rule lives in the prompt and as a post-check in our code — so even a hallucinating model cannot spend money or skip the human.
